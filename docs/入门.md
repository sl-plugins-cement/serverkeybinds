# ServerKeybinds 协作者入门

本库负责整台服务器的 Server-Specific Settings（服务器专属设置）：按键、下拉框、滑块、双按钮开关、分类和可见性。
它是共享依赖，每个服务器只安装一份，放在该端口 LabAPI 加载器实际读取的目录，不会作为独立玩法插件运行。

## 先运行完整示例

克隆 [教学示例仓库](https://github.com/sl-plugins-cement/scpsl-plugin-examples/tree/onboarding-foundations-zh)，按 `docs/start-here.md` 构建。
`examples/Foundations/Plugin.cs` 包含最小注册流程；不需要另建项目才能试用。
示例用 `SssIdBlocks.CementExamples`（1160000–1160999），仅供教学插件使用。

```csharp
KeybindBlock block = KeybindRegistry.ClaimBlock(SssIdBlocks.CementExamples, "Example.CementFoundations")
    .InCategory(SettingsCategory.Tools)
    .Header("入门练习")
    .VisibleTo(player => player.IsAlive)
    .Add(1, "使用教学硬币", KeyCode.V, "先接受建议按键或自己绑定。", OnUse)
    .AddTwoButtons(2, "教学 HUD", "显示", "隐藏", false, "只控制本示例显示。", OnHudChanged);
block.Enable();
// 插件关闭时：block.Disable();
```

`OnUse` 为 `Action<Player>`，`OnHudChanged` 为 `Action<Player, bool>`；双按钮回调 `true` 表示选中第二项，即这里的“隐藏”。
代码中的权限和业务条件必须在回调中再次检查。可见性用于呈现，不能代替当前物品、存活状态、冷却等业务检查。

## 必须保持的约定

- 每个消费者申请固定的 1000-ID 区块，在 `src/SssIdBlocks.cs` 登记；不要复制教学区块作为新产品 ID。
- 本地 ID 0 用于标题；设置使用 1–999。不要随意修改已发布 ID 或把同一 ID 换成另一种设置类型。
- 建议键 `SuggestedKey` 需要玩家接受，服务器不能替玩家强制绑定。
- 统一通过本库注册，不另行替换 `ServerSpecificSettingsSync.DefinedSettings`。
- 开启与关闭成对；事件、自己的玩家状态和协程也需要调用方清理。
- 公共接口只增不改；`ApiVersion` 仅用于启动日志识别，消费者不得探测它，也不得标注“需要 API N”。

本库接口依据：`src/KeybindBlock.cs`、`src/KeybindRegistry.cs`、`src/SssIdBlocks.cs`。
原生设置持久化依据：游戏源码 `UserSettings/ServerSpecific/ServerSpecificSettingBase.cs` 的 `GeneratePrefsKey`；
其中类型代码参与存储键，因此更换类型可能导致原设置不再被读取。

## 单独构建

```powershell
dotnet build ServerKeybinds.csproj -c Release -p:SCP_SL_MANAGED='D:\Servers\SCPSL\SCPSL_Data\Managed' -p:DeployToLocalServer=false
dotnet run --project tests/MusicPreferences.Unit/MusicPreferences.Unit.csproj -c Release
```

输出为 `bin/Release/net48/ServerKeybinds.dll`。测试命令覆盖已有音乐偏好逻辑，不证明客户端按键和菜单显示正确。
实际按键仍需真实客户端按 [示例验收清单](https://github.com/sl-plugins-cement/scpsl-plugin-examples/blob/onboarding-foundations-zh/tests/foundations-verification.md) 检查。

## 如何提交修改

每项任务开分支；共享元仓库用独立 worktree。PR 使用中文，说明调用方、设置 ID/类型是否变化、构建与实测结果。
新 API 应先保持旧调用兼容，再更新示例仓库的锁定提交。合并或发布前由另一位协作者评审。
不提交服务器配置、玩家数据或 DLL；生产部署由指定维护者执行。
